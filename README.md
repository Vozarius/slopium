# Slopium

Клиентское дополнение для **Minecraft 1.21.1 / NeoForge**, спроектированное по клиентским Spark-профилям. Текущая версия — **0.1.0-alpha.6**. Цель — снизить стоимость света и невидимых механизмов в насыщенных Create сценах. Достижение 60 FPS на двух исходных клиентах ещё не измерено.

**Установка:** поместить `slopium-neoforge-1.21.1-0.1.0-alpha.6.jar` из `build/libs` в `mods` клиента, заменив предыдущую версию, и перезапустить клиент. Существующая конфигурация сохраняется. Серверная установка не нужна. Требуется Sodium 0.8.13 для 1.21.1; проверяемая версия NeoForge — 21.1.242, Java 21. Настройки доступны в **Настройки графики → Slopium**; Reese’s Sodium Options поддерживается через API Sodium.

| Страница | Возможности |
|---|---|
| Тестовые отключения | Отдельные отключения BER, Flywheel, частиц, фоновых эффектов и диагностическая заморозка Create |
| Бюджет рендера | LOD стопок, радиусы предметов/BER, пауза бенчмарка Xaero, ограничитель Flywheel, тени |
| Радикальные эксперименты | Плоские изображения предметов, анимации трёх типов Create, бюджет частиц, дискретные текстуры |
| Общее | Общий выключатель для сравнения, счётчики диагностики, время кадров |
| Динамический свет | Пространственный поиск источников, кеш запросов на кадр, выключатели Create и Sable/Aeronautics |
| Видимость и обновления | Отсечение трещин разрушения вне камеры, экспериментальное разрежение тиков скрытых механизмов |

**Alpha.6:** [Настройки, ограничения и порядок тестирования](docs/ALPHA6_TESTS.ru.md). [Сравнение присланных скриншотов](analysis/alpha5-results.ru.md): сельская сцена 114 FPS, город 36,1 FPS. Это результаты alpha.5; alpha.6 ещё не измерена в пользовательском мире.

**Alpha.5:** [Новые настройки и порядок тестирования](docs/ALPHA5_TESTS.ru.md). Все новые переключатели выключены по умолчанию. [Кандидаты радикальных оптимизаций](docs/RADICAL_CLIENT_OPTIMIZATIONS.ru.md) описаны отдельно и не выдаются за реализованные функции.

**Alpha.4: диагностические отключения.** На новой странице пять независимых переключателей, все выключены по умолчанию. Они позволяют измерить выигрыш от исключения отдельных категорий работы. Это намеренное упрощение картинки, а не обещание 60 FPS или универсальный куллинг. Статические модели блоков, перестройка чанков, обработка пакетов и серверная симуляция остаются. Инструкция и ограничения: [docs/ALPHA4_TESTS.ru.md](docs/ALPHA4_TESTS.ru.md).

**Что включено по умолчанию.** Индекс и кеш света, отсечение трещин. Динамический свет остаётся включённым. Индекс сохраняет радиус 7,75 блока и формулу установленного Sodium Dynamic Lights; каждый снимок фиксирует координаты источников на кадр. Маленькие наборы источников обрабатываются простым проходом. Чужие JAR в Slopium не встраиваются.

**Выключатели Create Dynamic Lights.** Поддерживаются альтернативные реализации `2.3.1-sodium-sable` и `2.0.1`. У них один mod ID `createdynlight`; устанавливать обе одновременно нельзя. Поэтому меню показывает одну активную версию. Дополнительный выключатель Sable доступен для варианта 2.3.1. Slopium использует штатное удаление источников; при отключении Sable прекращается также сканирование. Исходные конфиги дополнения сохраняют приоритет: выключенный в них свет Slopium принудительно не включает.

**Экспериментальные тики выключены по умолчанию.** Для них нужен EntityCulling 1.10.5 и Create 6.0.11. Выбранные классы труб, баков, воронок, желобов и простых кинетических блоков за препятствиями обновляются реже. По умолчанию — раз в 4 тика, только за пределами 24 блоков и после 20 тиков невидимости. Видимость, пакеты обновления и приближение восстанавливают полную частоту. Ленты, поезда, контроллеры движущихся конструкций, неизвестные классы аддонов и Sable sub-levels исключены. Режим может менять клиентские анимации и звуки, поэтому требует проверки на реальной сборке.

Конфигурация: `config/slopium.json`. Команды `/slopium status` и `/slopium reset` показывают и сбрасывают диагностику. Alpha.3 отдельно измеряет интервалы между началами кадров: средний FPS, p50/p95/p99, максимум и долю интервалов дольше 16,67 мс. Сохраняются последние 16 384 интервала в мире с закрытым меню и без паузы. Процентили считаются по ближайшему рангу; это интервалы кадров, а не GPU-время. Общий выключатель возвращает штатные пути выполнения, включая свет Create; для изолированного сравнения нужно переключать конкретную оптимизацию. После применения настроек перестраивается клиентская геометрия чанков и сбрасывается замер кадров, поэтому перед новым измерением нужно дать ей стабилизироваться.

**Изменения alpha.3.** Исправлено отсечение трещин: обработчик перенесён в перегрузку NeoForge с `ModelData`, которую непосредственно вызывает рендер мира. Добавлены `checked cracks` и строка `Frames` в статусе. Для замера включить диагностику, выполнить `/slopium reset`, закрыть чат, провести минуту в тяжёлой сцене и сохранить все три строки `/slopium status`. Диагностика работает также при выключенных оптимизациях. Анализ alpha.2 и обоснование исправления: [analysis/alpha2-report.ru.md](analysis/alpha2-report.ru.md).

**Изменения alpha.2.** По профилю после установки alpha.1 устранены повторные поиски модов и классификация объектов на каждом тике, убран отменяемый callback из этой проверки. Пустой снимок света обрабатывается без кеширования координат. Новый вывод `/slopium status` объясняет, какие проверки тиков отклонены из-за видимости/исключений, защитного радиуса, Sable или неготовности объекта. Для диагностики выполнить `/slopium reset`, провести 60 секунд в тяжёлой сцене и сохранить обе строки `/slopium status`; числа относятся к проверкам тиков, а не уникальным объектам. Для итогового сравнения FPS диагностику выключить. Разбор нового профиля и границы исправления: [analysis/post-slopium-report.ru.md](analysis/post-slopium-report.ru.md).

Distant Horizons, настройки Java, приоритет процесса, серверная симуляция и сетевой протокол не изменяются. Данные EntityCulling и существующий Flywheel используются без второго фонового потока трассировки.

Подробное обоснование, границы текущей версии и план следующих оптимизаций: [docs/SLOPIUM_DESIGN.ru.md](docs/SLOPIUM_DESIGN.ru.md). Исходный анализ: [analysis/client-performance-report.ru.md](analysis/client-performance-report.ru.md).

Результаты выполненных проверок и ограничения замеров: [docs/VALIDATION.ru.md](docs/VALIDATION.ru.md). Двенадцать модульных тестов и проверки запуска пройдены. Первый присланный замер кадров alpha.3: **28,8 FPS**, p95 **50,62 мс**; цель 60 FPS не достигнута, сопоставимый исходный FPS ещё не измерен. Исправленное отсечение трещин срабатывает, но основной расход тиков и рендера сохраняется. [Разбор alpha.3 и оценка следующего этапа](analysis/alpha3-report.ru.md).

**Сборка из исходников.** В `reference/mods` должны находиться исходные JAR Sodium, Create, Sodium Dynamic Lights и EntityCulling. Они используются только при компиляции и локальных проверках. Требуется JDK 21.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
.\gradlew.bat build
```

Для проверки настоящего меню в отдельном тестовом клиенте:

```powershell
.\gradlew.bat runSmokeClient -PwithReferenceMods
.\gradlew.bat runSmokeClient -PwithReferenceMods -PsmokeProfile=legacy
.\gradlew.bat runSmokeClient -PwithReferenceMods -PsmokeProfile=minimal
```

Профили запускаются в `run/smoke-full`, `run/smoke-legacy`, `run/smoke-minimal`. Они используют копии модов, проверяют регистрацию страниц и доступные адаптеры, сохраняют снимок экрана и закрываются. Тестовый мод находится в `src/smoke` и **не входит в выпускной JAR**. Обычный `runClient` его не загружает. Не следует добавлять личные миры и моды в эти тестовые каталоги.

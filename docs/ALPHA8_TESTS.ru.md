# Slopium alpha.8 — куллинг за стенами

Иконка из `reference/logoT.png` используется без изменения изображения: в метаданных NeoForge и в меню Sodium/Reese. Новая страница — «Куллинг за стенами». Все новые переключатели выключены по умолчанию.

## Реализовано

- **Частицы за стенами:** исключается вызов рендера частицы стандартного ParticleEngine, если центр и восемь углов расширенной области перекрыты непрозрачными полными блоками. Движение, старение и создание частиц продолжаются; эффект возвращается с актуальным возрастом. Отсечение вне экрана уже есть в NeoForge; новый режим добавляет проверку за геометрией перед записью вершин. Нестандартные движки частиц не охвачены.
- **Считать стекло стеной:** только для предыдущего режима частиц. Дополнительно полные коллизионные кубы, включая стекло, могут скрывать частицы. Стеклянные панели, вода, ступеньки и остальные неполные формы не считаются полной стеной.
- **Рендер Create за стенами:** отмена обычного Sodium BER-вызова SmartBlockEntity Create до работы его рендерера. Используются его render bounds с запасом, а не точка в центре блока. Статическая часть блока в геометрии чанка остаётся под управлением Sodium.
- **Экземпляры Flywheel за стенами:** скрываются через `Instance.setVisible(false)`, не отменой всего графического прохода. Охвачены точные классы SingleAxisRotatingVisual, ShaftVisual, PressVisual, MixerVisual, FunnelVisual. Коллекция экземпляров берётся через проверенный collectCrumblingInstances этих типов. Неизвестные подклассы и прочие визуализации не затрагиваются. Восстанавливаются только экземпляры, которые скрыл Slopium; изначально невидимые остаются невидимыми.
- **Анимации Create за стенами:** отдельно пропускаются beginFrame у PressVisual, MixerVisual, FunnelVisual. Рабочие потоки Flywheel читают результат проверки текущего кадра; мир на них не обходится. Удаление, создание экземпляров, обновление света, обработка пакетов и обслуживание движка не отменяются.
- **Редкие тики Create за стенами:** экспериментальная политика для SmartBlockEntity. После hiddenGraceTicks работает один тик из hiddenTickInterval (параметры старой страницы «Видимость и обновления»). Ближняя зона 4 блока от игрока, целевой блок, открытое меню, инициализация, виртуальные объекты и Sable исключаются. Пакеты read будят TickGate. Серверные миры отсекаются до обращения к клиенту. Клиентские таймеры/анимации/звуки всё равно могут замедлиться — универсальная поведенческая совместимость аддонов не заявляется.
- **Скрыть все соединения фабричных панелей:** диагностическое отключение renderPath без радиуса, включая рядом с игроком. Предметы, индикаторы и панели не исчезают; серверные связи не удаляются. Проверяет именно стоимость линий.

## Почему прежние панели могли не дать выигрыша

Alpha.7 скрывала линии только за радиусом, сохраняла их рядом с любым концом, при наведении, в меню и при защите Sable. Это не оптимизировало всю панель и не исключало предметы из SmartBlockEntityRenderer. У FactoryPanelBlockEntity render bounds дополнительно расширены на 8 блоков — обрезать весь контроллер по одному кубику было бы некорректно для его соединений. Без профиля/счётчика нельзя назвать одну причину отсутствия выигрыша именно в пользовательском тесте. Новый безусловный тумблер позволяет изолировать стоимость линий.

## Ограничения алгоритма

Это **приближённый**, не точный попиксельный куллинг. Проверяются девять направлений к расширенным границам, общие области округляются наружу по сетке 2 блока. Узкое отверстие между лучами может вызвать ошибочное исчезновение. Большой bounding box, касающийся стены или камеры, наоборот может мешать отсечению. Поэтому режимы тестовые.

Есть общий кеш до 8192 областей, срок до четырёх кадров, сброс при изменении блоков, мира, настроек и перемещении камеры более чем на 0.25 блока от опорной позиции. При меньшем смещении возможна краткая задержка. Проверки ограничены 256 лучами и 8192 посещениями блоков на кадр; после примерно 1 мс накопленных проверок новые задачи не запускаются (одна уже начатая задача может превысить временной ориентир). При исчерпании бюджета или неизвестном чанке объект остаётся видимым. В очень плотной сцене бюджет может ограничить охват. Дальность проверок — до 128 блоков от центра bounds; средний размер bounds более 32 блоков и бесконечные bounds исключены.

Sable-плоты и камера внутри них исключены, чтобы не принимать координаты хранилища за мировой ландшафт. Движущиеся конструкции не превращаются в статические окклюдеры. Проверки Flywheel выполняются на основном потоке после ожидания tick-задач и до запуска frame-задач/компактизации экземпляров. На выключение восстанавливается видимость при следующем beginFrame соответствующего менеджера.

## Проверка

Старые полные отключения частиц, BER, Flywheel и заморозку Create выключить, иначе они перекроют новые режимы. Сравнивать по одному переключателю, затем комбинацию. Диагностику включить, `/slopium reset`, 60–90 секунд с закрытым чатом, `/slopium status`.

1. Источник частиц перед камерой, затем за сплошной стеной. Частицы за стеной перестают рендериться, открытые сохраняются. Повторить со стеклом и обоими состояниями дополнительного тумблера.
2. Завод за стеной: отдельно BER, Flywheel, анимации и тики. Обойти/сломать стену, открыть дверь, вернуться, выключить настройки. Проверить восстановление объектов, включая после обновления механизма.
3. Стена фабричных панелей: включить только «Скрыть все соединения». Линии должны исчезнуть даже вблизи. Если FPS почти не меняется, следующий профиль нужен для остальных частей панели, а не для дальнейшего урезания линий.
4. Не ограничиваться средним FPS: сравнить p95/p99 и долю кадров дольше 16.67 мс.

В статусе строка `Walls`: particles/Create draws — пропуски рендера, Create ticks — пропуски тиков, Flywheel instances — число переходов экземпляров в скрытое состояние (не число исключённых draw calls), rays/cache/budget misses — стоимость и охват проверок. Счётчик Create visual frames общий с прежним ограничением анимаций по дальности.

Фактический выигрыш FPS в пользовательском мире не измерен. Эти изменения направлены на частицы и Create, но не доказывают, что других узких мест нет, и не гарантируют 60 FPS или равенство 5/32 чанков.

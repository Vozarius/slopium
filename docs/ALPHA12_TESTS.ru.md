# Alpha.12: обёртки Azimuth и скрытие Flywheel

## Причина

В пользовательском отчёте `Walls → Create draws=8514`, `Flywheel instances=0`, `Sable protected=0`. Это показывает работу обычного пути Create, но не скрытие экземпляров Flywheel. Нулевой `Walls → rays` относился к старому общему трассировщику; Create использует отдельный бюджет. Теперь его лучи и кеш видны в `Create visibility`.

Azimuth 1.4.9 создаёт `WrappedVisual` вокруг исходной визуализации Create, когда присутствуют визуальные расширения, в том числе Bits 'n' Bobs 2.3.5. Обёртка не наследует AbstractBlockEntityVisual и не входит в список проверенных классов Slopium. Поэтому alpha.11 пропускала её ещё до проверки препятствий. Это воспроизведено на настоящем классе WrappedVisual из reference-мода: тест прежнего обработчика завершился `Actual Flywheel manager policy did not hide instance` (build/alpha12-repro-full.log).

## Исправление

Опциональный accessor читает исходный delegateVisual. Проверка типа, положение блока, владение экземплярами и пауза относятся к исходной проверенной визуализации; учёт живых объектов относится к внешней обёртке в хранилище Flywheel. Используется прямой accessor без отражения в каждом кадре, максимум восемь проверок цепочки. Неизвестные или некорректные цепочки остаются видимыми.

Список экземпляров скрытой модели обновляется каждый кадр. Это необходимо для BnB, который может заменить rotatingModel при смене материала. Новая модель скрывается, снятые экземпляры забываются и не восстанавливаются. Изначально скрытые экземпляры Slopium не присваивает себе.

При изменениях блоков кеш ответов Create очищается, но очередь запросов сохраняется и проверяется по новой геометрии. Смена мира или позиции камеры по-прежнему очищает обе структуры. Лимиты трассировки не увеличены: 1024 луча, 32768 шагов и около 1 мс накопленной трассировки за кадр. Нехватка бюджета оставляет объект видимым до проверки.

## Область проверки

Новый интеграционный сценарий использует настоящий WrappedVisual и расширение CogwheelChainBehaviourVisual из модов, LargeCogVisual и RotatingInstance Create, искусственный ClientLevel и тестовые handles. В полном профиле подключается настоящий пустой ClientSubLevelContainer Sable: обычная территория разрешает проверку, область Sable защищена. Мировые тесты больше не пропускаются только из-за наличия Sable.

Проверяются скрытие шестерни и дополнительного вала за соседней стеклянной панелью, раздельные режимы препятствий для моделей/анимаций, снятие стекла, полная пауза, общий выключатель, замена rotatingModel и сохранение дополнительной геометрии расширения. При холодном запуске тест допускает до десяти кадров для выполнения штатной очереди, без увеличения бюджета.

Отдельный тест настоящего InstancedInstancer/InstanceHandleImpl подтверждает удаление скрытых экземпляров при compaction и восстановление только своих экземпляров: количество 2 → 0 → 1 → 0. Тест не создаёт полноценную GPU-сцену и не измеряет FPS. Фактический writer ROTATING проверяется через запись скорости/угла в native buffer.

Тест очереди Create откладывает запрос, меняет геометрию, затем проверяет, что запрос обслужен раньше новых и использует актуальные блоки. Проверяется также сброс скрытого результата при проходе камеры через окно. Тест ParticleEngine выполняется и с Sable, используя тот же изолированный контейнер.

## Ограничения и проверка в игре

Это исправление поддержки известных визуализаций, а не скрытие всех моделей всех аддонов. Статическая геометрия чанков, цепи BnB и другие непроверенные расширения не исчезают автоматически. Отсечение по центру агрессивное: части модели могут пропадать у края препятствия. Режим «За любыми блоками» учитывает форму блока; пустое отверстие не считается стеной. Объект под прицелом, открытое меню, неизвестные чанки и Sable сохраняют защиту.

Заменить все прежние JAR Slopium в клиентской папке mods одним alpha.12, перезапустить игру. Конфигурацию удалять не нужно. В «Create: модели и анимации» оставить для моделей Flywheel «За любыми блоками», закрыть меню. Сравнить вращающиеся детали за тем же окном с режимом «За непрозрачными блоками», затем с отключённым скрытием. Для паузы выбрать «Приостановить везде», временно оставив модели видимыми.

В `/slopium status` строка `Flywheel visibility` содержит накопительные количества обходов: `checked`, `wrapped`, `unsupported`. Это не число уникальных механизмов. `Walls → Flywheel instances` считает переходы экземпляров в скрытое состояние, а не число скрытых объектов прямо сейчас. `Create visibility → rays/cache/deferred` отражает отдельный трассировщик Create. Много `deferred` означает нехватку бюджета, не ошибку стекла само по себе.

Фактический FPS пользовательского сервера в alpha.12 пока не измерен; 60/400 FPS не обещаются. Серверные тики, пакеты и механика сервера этим исправлением не меняются.

# Alpha.5: бюджет рендера

Новая страница Slopium → Бюджет рендера. F3, DH, сеть и серверная симуляция не изменены. Новые режимы выключены по умолчанию, чтобы старый конфиг не менял картинку без выбора пользователя. Старые диагностические отключения остаются на отдельной странице.

| Опция | Действие и цена |
|---|---|
| Упрощать дальние стопки | За радиусом оставляет одну визуальную копию вместо 2–5. Исходный ItemStack не копируется и не изменяется; счёт, подбор и клиентские тики сохраняются. Контекст ограничен рендером ItemEntity и восстанавливается через finally, не влияет на инвентарь/JEI. |
| Дальность предметов | Полностью скрывает модели далёких выпавших предметов. Не удаляет сущности. Не заменяет LOD. |
| Дальность блочных сущностей | Ранний выход из Sodium.renderBlockEntity до подготовки матриц, трещин и вызова BER. Учитывает границы рендерера, сохраняет модель при пересечении радиуса. Обычные блоки и отдельный Flywheel остаются. Sable-защищённые позиции исключены. |
| Xaero: приостановить GPU-бенчмарк | В TextureUploader.uploadTextures пропускает только две проверки, запускающие измерение. Сами upload.run, addToPool и очистка очереди выполняются. Данные бенчмарка не подделываются, requestUpload использует штатные оценки, пока измерение не завершено. Выключение режима возобновляет калибровку. Карта может обновляться медленнее из-за консервативных оценок. |
| Разрежать дальние обновления Flywheel | Штатный DistanceUpdateLimiter: NonLimiter получает период, BandedPrimeLimiter использует максимум своего периода и выбранного. Расписания не перемножаются, исходная частота не повышается. Обслуживание очередей, ресурсов и тики мира не отменяются. Дальние анимации менее плавные. |
| Не рисовать тени | Отменяет обычные проекционные тени EntityRenderDispatcher. Не управляет тенями сторонних шейдеров. |

Полное отключение BER из alpha.4 теперь дополнительно обрывает весь публичный проход Sodium до обхода списков. Старый dispatcher-хук остаётся для сторонних путей. Поэтому старый счётчик BE draws может стать меньше: пропуск теперь виден в новом счётчике Sodium passes.

Радиусы задаются в блоках. Предметы и BER дополнительно ограничены текущей дальностью обычных чанков. При 12 чанках эффективный максимум 192 блока; при 5 — 80. Шкала хранит настройки до 512 блоков, чтобы не терять их при временном уменьшении дальности. Радиальная сфера не совпадает с квадратом загруженных чанков. Выключатель полностью отменяет ограничение. Нулевой радиус сохраняет только модель, границы которой содержат камеру. Для Flywheel используется расстояние, передаваемое самой визуализацией; это не универсальная проверка мировых границ Sable.

**Охват Flywheel ограничен.** В эталонном Create прямой вызов doDistanceLimitThisFrame найден только у BlazeBurnerVisual. Этот переключатель не является общей оптимизацией всех валов, лент, подвижных конструкций и GPU-буферов. Дополнения могут использовать API самостоятельно. Более широкий планировщик визуализаций требует отдельного аудита.

## С чего начать проверку

Оставить тестовые полные отключения и заморозку Create выключенными. Сначала сравнить исходный режим и только LOD стопок (16 блоков). Затем отдельно Xaero benchmark и тени. Для завода отдельно проверить BER с радиусом 32/64 блока и раннее полное отключение BER. Flywheel — отдельный эксперимент, ожидаемый охват небольшой.

В одинаковой сцене после прогрева: диагностика включена → /slopium reset → 60 секунд без меню → /slopium status. Сохранить строку Render budget: item draws, copies, shadows, Sodium passes, Xaero guards. Счётчики отражают вызовы, не уникальные объекты; Xaero guards содержит две проверки на одну измеряемую загрузку. Нулевые значения при отсутствии соответствующей работы нормальны.

При включённом полном отключении BER радиус BER не влияет на результат. LOD не виден там, где предмет уже полностью скрыт радиусом. Статические модели механизмов и визуализации Flywheel не обязаны исчезать вместе с BER. 60/400 FPS этой версией не измерены.

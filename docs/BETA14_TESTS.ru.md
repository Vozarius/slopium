# Бета 14 — GPU-маска секций

7 ноября 2026. Minecraft 1.21.1, NeoForge 21.1.242, Sodium 0.8.13, Create 6.0.11, Flywheel 1.0.6. Стенд: i5-12400F, RTX 4060 Ti, Windows 11, NVIDIA 621.01, Java 21.0.9. Изолированные миры в `run/smoke-legacy` и `run/smoke-full`; пользовательские Minecraft, mods и конфиги не изменялись.

## Что заменено

Удалены `SectionProof`, `SectionOcclusion`, `SectionMeshes`, `SectionRegionState`, `SectionRegionMixin`, очередь CPU-доказательств секций, witness-кеш секций и CPU-ветки sectionHidden. `SectionVisibility` теперь содержит только политику и диагностику. В VisibilityPool остались прежние точечные запросы других функций; секции туда больше не поступают. Старый дополнительный проход стекла Flywheel не выполняется одновременно с новой маской секций.

Новый `GpuSections` использует только готовые списки Sodium: кандидатов с terrain-геометрией и с Block Entity. Второй список нужен в том числе для секций, состоящих из валов Flywheel без обычного terrain-меша. Обхода блоков мира нет. Стекло помечается во время штатной сборки меша, до вызова кодировщика, поэтому метка работает как с CompactChunkVertex, так и с заменой кодировщика Veil из Sable.

До основного цвета рисуются глубина и R32UI ID кандидатов. Политика OPAQUE использует solid/cutout с исходным alpha discard; ANY дополнительно использует translucent-поверхности и полную поверхность известных стеклянных моделей. Проёмы, заданные геометрией, не заполняются. Обычные cutout-модели, например листья, сохраняют альфа-маску.

GPU отмечает секции, давшие ближайшие образцы. Одного ID недостаточно для совпадающих поверхностей: дополнительно проверяется консервативная проекция объёма секции против max-depth-пирамиды. Равные глубины, пересечение near plane и недоказанное перекрытие сохраняют секцию. Объём расширен до допустимого диапазона координат вершин Sodium/Veil: локальные −8…24, а не ошибочное предположение 0…16. Поэтому частично закрытые секции иногда остаются видимыми даже при фактически закрытой небольшой модели внутри.

Первая стадия пирамиды объединяет 4×4 **исходных** пикселя максимумом глубины. Глубина препятствий растеризуется в полном разрешении. Каждый исходный образец учитывается; один открытый пиксель сохраняет отверстие в консервативной проверке. Массовые atomic-записи одинакового ID заменены записями на границах областей. Убраны ненужные верхние уровни пирамиды.

Маска применяется compute-проходом к indirect-командам Sodium. Команды кешируются до изменения batch; решения видимости не кешируются между кадрами. Ни чтения маски CPU, ни ожидания GPU в рабочем пути нет. GPU-таймер использует отложенные timestamp queries без ожидания готовности. Тестовый source set отдельно копирует маску и команды после fence; этот код не включён в JAR и не участвует в решениях рендера.

## Единая политика и совместимость

Существующие frustum, защищённый радиус, дальность, OPAQUE/ANY и GPU-тумблер формируют одну маску. В пределах защищённого куба сохраняется штатное поведение Sodium. Радиус 0 защищает секцию камеры. Настройки не добавлены второй раз.

Flywheel indirect читает тот же SSBO и GPU-таблицу координат секций. Используются только экземпляры обычного мира с надёжно ограниченной bounding sphere, при выборе «Все» в списке блоков. Для оставшихся экземпляров сохраняется штатный per-instance куллинг Flywheel: он нужен внутри частично видимых секций. Селективные списки, instancing-backend, неизвестные привязки и виртуальные/вложенные миры не получают дополнительного отсечения этой маской.

Общие batched-рендеры обычных Block Entity не несут надёжного ID владельца на draw. Их CPU-проверка не дублирует новый проход, а специальная геометрия остаётся видимой. Полные отключения и независимые ограничения дальности сохранены. GPU-маска не меняет тики, анимационные обновления, сеть, симуляцию или загрузку чанков; старые самостоятельные настройки этих функций не переписаны. Distant Horizons не изменён.

MSAA, Iris/Oculus, нестандартные framebuffer/viewport и неподдерживаемые GPU оставляют кандидатов видимыми. Это безопасное отключение дополнительного отсечения, а не заявленная поддержка этих путей. Неизвестные разновидности cutout-стекла сторонних модов могут остаться прозрачными для глубины.

## Проверки

GPU oracle проверяет скрытую, ближнюю и совпадающую глубину, near plane, защищённый радиус, frustum on/off, сохранение ID и отверстие. Исправлены два дефекта самого тестового стенда: наследование pixel-unpack state Minecraft и отсутствие SSBO-барьера между двумя последовательными тестовыми dispatch. Один из ранних тестов до исправления unpack state вызвал native-сбой драйвера; итоговый рабочий рендер этот путь загрузки текстуры не использует.

`build/beta14-gpu-ab8.log`: 22 фазы реального игрового рендера прошли. Проверены стекло в обоих режимах, камень, защищённый радиус, отключение/включение, удаление стены, движение камеры, оконные панели Create на разных плоскостях, удаление панели, поворот назад и обратно, частично видимая секция, угол из двух стен, открытие угла, cutout-листва и замена её сплошной стеной. Для каждого доступного целевого кандидата проверены 60 последовательных GPU-снимков без несовпадений; проверены не только биты маски, но и наличие привязанных indirect-команд и их instanceCount. В двух фазах дополнительное отсечение выключено либо сам Sodium уже исключил кандидата.

Снимки `run/smoke-legacy/screenshots/beta14-section-7.png` и `...-8.png` визуально подтверждают отличие ANY/OPAQUE: дальние валы исчезают только в ANY. Снимки 18–21 показывают угол, проём, листву и стену. В этих проверках не наблюдалось пропадания видимого целевого кандидата или мерцания его маски. Это ограниченный регрессионный стенд, не утверждение о всех возможных ресурс-паках и серверных постройках.

Первый полный запуск (`build/beta14-full-world-ab.log`) обнаружил потерю метки стекла при использовании VeilChunkVertex. Исправление перенесено с конкретного кодировщика в общий ChunkMeshBufferBuilder. Экспорт преобразованного класса выявил дополнительную ошибку hook: короткое имя push выбирало не ту перегрузку, основной путь оставался без метки. Исправлено полным дескриптором push(Vertex[], int); тест проверяет фактические байты материала и ID секции. Итог полного повторного прогона и сборки приведён ниже.

## A/B и стоимость

Измеряется настоящая игровая петля, генерация кадров и VSync выключены. Камера фиксирована, 1280×720, дальность 4. В мире размещены 9216 валов Create и 24 обычных блока-корпуса в их секциях; фактический список кандидатов зависит от Sodium. Прогрев 40 секунд, затем четыре чередования OFF/ON/OFF/ON: 4 секунды на переключение и 15 секунд измерения. CPU — время отправки depth/visibility-прохода; GPU — отложенные timestamps этого прохода, **не вся стоимость всех indirect draw**.

Ранний простой стенд без корпусов (`ab6`) показал после прогрева 1,178 мс OFF против 1,290 мс ON. Затем проверка расширена на кандидатов с Block Entity, кешированы команды и уменьшена работа пирамиды/атомиков. Этот ранний результат не выдаётся за ускорение.

Повтор `build/beta14-gpu-ab8.log`:

**Устойчивый прирост FPS не подтверждён.** Средние сильно колеблются; медиана с отсечением здесь хуже. Нельзя выбирать только выгодную пару. GPU-проход стал дешевле, но простые инстансированные валы на RTX 4060 Ti сами рисуются дёшево, а клиентские/серверные обновления эта функция не ускоряет. Дополнительное отсечение остаётся выключенным по умолчанию. Данный стенд не заменяет A/B на пользовательском заводе и не доказывает 60/400 FPS.

## Итог полного набора

`build/beta14-full-world-ab6.log`: GPU oracle и все 22 игровых сценария прошли на полном reference-наборе, включая Veil/Sable, Azimuth, Distant Horizons, Sodium Extra и BetterChunkLoading. В мешах Veil подтверждена метка материала (130), в обычном Sodium отдельный oracle подтверждает сохранение всех битов материала и ID секции. Для полного A/B дополнительно зафиксированы время суток и погода, выключены случайные тики и удалены выпавшие предметы **только в тестовом мире**. Distant Horizons и его настройки не отключались. Дальность 4 запрашивается стендом при старте; полная сборка также применяет собственные настройки DH. Здесь дополнительное отсечение снижало средние FPS примерно на 4–12%. Снимки `run/smoke-full/screenshots/beta14-ab-0.png` и `...-1.png` подтверждают фактическое уменьшение видимых валов, но работа с кадром в целом не ускорилась. Это не основание включать функцию ради FPS на любой машине. Исправленная маска и более дешёвая пирамида являются проверенной функциональной заменой нестабильного CPU-отсечения; положительный выигрыш на пользовательском заводе ещё не доказан. Большие дальности, другие GPU и активные фабрики требуют отдельного A/B.

`build/beta14-final-ui-build2.log`: итоговая сборка, GPU/material oracle с обычным CompactChunkVertex, реальные зарегистрированные Sodium-опции, отсутствие повторяющихся ID, зависимости и ограничения радиуса, семь страниц меню, ввод чисел и список блоков прошли. В старом тесте Flywheel исправлен вызов обработчика с недостающим RenderContext; рабочий обработчик ради теста не упрощался.

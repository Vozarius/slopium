# Alpha.6: радикальные эксперименты

Страница Slopium → Радикальные эксперименты. Все новые опции выключены по умолчанию; старые настройки сохраняются. Общий выключатель Slopium отменяет новые режимы. F3, настройки DH и серверные тики не изменяются.

## Плоские изображения дальних предметов

За радиусом обычная ItemEntity-модель заменяется одним прямоугольником, обращённым к камере, с particle-текстурой исходной модели. Используется общий атлас и RenderType: штатные буферы могут группировать геометрию. Это не полноценный instancing или точная копия исходной модели. Для блока картинка представляет плоский образец материала; объём, вращение и нестандартные прозрачные эффекты могут исчезнуть. Размер фиксирован.

Именованные предметы, foil/зачарованные предметы и custom-rendered модели сохраняют обычный рендер. Стек, количество, сетевое состояние и подбор не изменяются. В инвентаре/JEI этот режим не применяется. Нет удерживаемого кеша спрайтов: при перезагрузке ресурсов берётся текущая модель. Радиус предметов alpha.5 имеет приоритет: за ним не будет ни модели, ни плоского изображения.

Начальный радиус — 24 блока. Для чистого теста отключить ограничение дальности предметов, чтобы не скрыть объекты до применения нового режима.

## Разрежение визуальных обновлений Create

Аудированы три точных класса: PressVisual, MixerVisual, FunnelVisual. Их beginFrame обновляет трансформации из текущего состояния анимации. За радиусом обновление выполняется раз в N кадров; добавляется 4 блока запаса для выступающих частей. Первый вызов, возврат в ближнюю зону и выключение режима допускают обновление сразу. Это ступенчатое движение модели, не заморозка клиентского блока.

Клиентские тики блока, приём пакетов, световые обновления, создание/удаление визуализаций и обслуживание GPU остаются. Подклассы дополнений, виртуальные миры и защищённые Sable-позиции исключены. Неизвестная интеграция Sable сохраняет визуальные обновления. Режим не распространяется на все механизмы, поезда, стеклянные трубы, движущиеся конструкции и прочие Flywheel-визуализации.

Начать с радиуса 24–32 и интервала 3. Большие интервалы усиливают ступенчатость. Наличие миллионов тиков в профиле не означает миллионы подходящих визуализаций. Счётчик Create visual frames измеряет только отменённые beginFrame. Для вызовов из рабочих потоков используется LongAdder; сброс во время выполнения задач приблизителен.

## Бюджет новых частиц

Ограничивает добавление стандартных ParticleEngine-частиц за клиентский тик; по умолчанию 128, возможен 0. Отбрасывает лишние запросы, не копит очередь на будущие кадры. Старые частицы продолжают стареть и удаляться. Смена мира/очистка частиц сбрасывает бюджет. Полное отключение частиц alpha.4 имеет приоритет.

Это общий лимит, без разделения декоративных и информативных эффектов: дым, следы, эффекты зелий и подсказки могут стать менее заметны. Сторонние системы частиц могут обходить этот путь. При отсутствии частиц прироста ждать не следует.

## Отключение интерполяции текстур

Отменяет только стандартный SpriteContents.InterpolationData.uploadInterpolatedFrame: промежуточное смешивание пикселей и его загрузку. Счётчики времени анимации и загрузка ключевых кадров остаются. Текстуры продолжают анимироваться с более резкими переходами. Общий атлас используется и интерфейсом, поэтому эффект виден также в инвентаре. Статические текстуры и нестандартные анимационные движки не затрагиваются; Sodium Extra/ресурс-пак могут уже устранять эту работу.

## Как сравнивать

Сохранить прежние настройки и сначала снять базовый замер. Затем включать новые опции по одной: тот же ракурс, прогрузка, 60–90 секунд без меню, /slopium reset перед замером, /slopium status после. Новая строка Radical: item sprites, Create visual frames, particles rejected, texture blends. Счётчики подтверждают действие, но не измеряют ускорение.

Для города первым проверить режим анимаций Create, если в сцене есть эти механизмы. Для предметов — плоский LOD. Бюджет частиц и текстурная интерполяция помогут только при соответствующей нагрузке. Нужен новый Spark-профиль для поиска оставшегося главного ограничения. Динамическое разрешение, универсальная GPU-окклюзия и упрощённые модели целых заводов в alpha.6 не реализованы.

# Alpha.19 — генерация кадров

Новая страница Sodium/Reese: **Генерация кадров**. Значения: **Выкл**, **Простая ×2**, **FSR 3 ×2 (тест)**. Новая функция по умолчанию выключена. Старые настройки и иконка logoT сохраняются.

## Что реализовано

- Общий захват цветового буфера и глубины до руки/HUD. Очерёдность вывода: A, промежуточный A/B, B, промежуточный B/C, C. На кадрах B/C повторная отрисовка мира не вызывается. Игровые тики, прицеливание и сетевые пакеты не отменяются.
- Простой режим: матрицы камеры и глубина дают начальные векторы; ограниченный поиск по двум изображениям уточняет движение объектов. Прямые/обратные векторы хранятся в RGBA16F-текстуре. Несогласованные участки используют текущий пиксель. Это интерполяция с перемещением изображения, не простое смешивание двух полноэкранных картинок.
- FSR: официальный подписанный `amd_fidelityfx_framegeneration_dx12.dll` из FidelityFX SDK v2.3.0, выбран поставщик **3.1.6**. Входные данные — цвет без HUD, глубина, векторы движения камеры; движение объектов дополнительно оценивает optical flow FSR. Настоящих per-object motion vectors от всех модов Minecraft нет.
- Нативный мост выбирает D3D12-адаптер по LUID текущего OpenGL-контекста. Цвет/глубина/векторы/результат обмениваются через shared textures и D3D12 fence, импортированный в GL semaphore. Чтения изображения на CPU в рабочем коде нет.
- Три D3D12 command allocator переиспользуются после завершения соответствующей GPU-работы. Если GPU отстал, освобождение allocator может ожидать fence; это не обещание полной асинхронности. При отключении/смене размера выполняется завершение работы перед освобождением памяти.
- История сбрасывается при смене мира, размера, режима, резком повороте/перемещении камеры и длинной паузе. Меню, загрузка и потеря фокуса временно прекращают генерацию; в загруженном мире GPU-ресурсы сохраняются, чтобы не создавать дорогой FSR-контекст заново после каждого сообщения в чате. При ошибке функция отключается до следующего Apply; FSR не подменяется простым генератором.
- `/slopium status`: настоящие кадры, промежуточные кадры, вывод готовых кадров, базовая/выходная частота. При включённой диагностике — время GPU, полученное из отложенных timestamp queries без ожидания результата в кадре.

## Настройки

| Параметр | Применение |
|---|---|
| Предел FPS с генерацией | Оба режима, 30–240; меньший лимит Minecraft/VSync сохраняется |
| Шаг сетки 4–16 пикселей | Простой режим; меньший шаг даёт больше векторов и больше работы GPU |
| Поиск 4–32 пикселя | Простой режим; поиск остаточного движения относительно камеры |
| Допуск 1–16 пикселей | Простой режим; порог несогласованности прямых/обратных векторов |
| Диагностическое изображение FSR | FSR; отладочные поля AMD вместо обычного промежуточного изображения |

Начать можно с простого режима, 120 FPS, сетка 8, поиск 16, допуск 4. FSR не использует апскейлинг: разрешение исходного кадра не меняется, поэтому «Quality/Balanced/Performance» здесь не означали бы реальные режимы SDK.

## Проверки GPU

В настоящем OpenGL-контексте проверены компиляция шейдеров, перемещение цветного прямоугольника в промежуточную позицию, создание FSR-контекста, импорт shared textures, семафоры и получение непустого результата двух вызовов FSR. Производственный обработчик отдельно проверяется на настоящем главном framebuffer с тестовым объектом мира: 5 выводов / 3 вызова отрисовки, сохранение глубины, переключение OFF, лимит FPS и прохождение исключений оригинального рендера.

Синтетические прогоны 1280×720 оказались нестабильными. Быстрые измерения: простой режим **0,2–0,3 мс**, FSR **1–4 мс** на промежуточный кадр. Поздние контрольные запуски: simple **5,25/5,55 мс**, FSR **16,15/47,27 мс**; ещё один повтор full дал **23,61 мс для FSR**. Причина разброса не установлена. Timestamp-интервал включает синхронизацию между API и может включать ожидание GPU/подачи команд. Это не гарантия ускорения и не замер FPS в игровом мире. Все значения и соответствующие журналы сохранены в метаданных сборки; медленные повторы не исключены из отчёта.

23 unit-теста прошли. Изолированные профили **full**, **legacy**, **minimal** завершились успешно: обе GPU-реализации, производственный обработчик, повторное использование ресурсов при паузе, свежая история после возврата, 54 параметра и семь страниц Sodium/Reese. Логи: `build/alpha19-full-final.log`, `build/alpha19-legacy-release.log`, `build/alpha19-minimal-final.log`.

Финальные результаты, все сохранённые GPU-замеры и контрольная сумма JAR: `analysis/slopium-alpha19-build.json`.

## Ограничения и проверка в мире

Генерация добавляет задержку, поскольку нужны два настоящих кадра. Она не превращает 30 настоящих FPS в отзывчивость 60 FPS. При полной загрузке GPU затраты генератора могут уменьшить базовую частоту. Частицы, прозрачность, быстро вращающиеся валы, открывающиеся из-за препятствий поверхности и резкие изменения освещения могут давать артефакты. Рука и HUD обновляются отдельно; поздние модовые обработчики AFTER_LEVEL также остаются вне захвата.

Нет подтверждённого сравнения OFF/SIMPLE/FSR в пользовательском серверном мире. Для него нужны одинаковые позиция, разрешение, направление камеры, нагрузка и лимиты. Включить диагностику, закрыть меню, сбросить счётчики и записать базовый FPS, выходной FPS и GPU generation для каждого режима. Сравнивать также задержку управления и артефакты, а не только число выходных кадров.

FSR проверен на Windows x64 / NVIDIA RTX 4060 Ti. Работоспособность на AMD/Intel и других драйверах этим тестом не подтверждается. При отсутствии необходимых GL/D3D12 возможностей режим сообщает отказ и сохраняет обычную отрисовку. Iris/Oculus, Fabulous, сторонняя генерация кадров и HDR-буферы исключены из этой интеграции.

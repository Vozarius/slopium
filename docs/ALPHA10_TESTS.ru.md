# Alpha.10: окно и понятные настройки

## Исправление частиц

Alpha.9 передавала getRenderBoundingBox в общую проверку стен. В базовом Particle эта область расширена на один блок; WallOcclusion дополнительно округлял её и исключал все блоки, пересекающие область объекта. Поэтому стеклянная панель рядом с частицей могла полностью исключаться из проверки. Камера внутри расширенной области также приводила к пропуску. Общий бюджет с Create добавлял независимый источник пропусков в нагруженных сценах.

В alpha.10 проверяется интерполированный центр частицы, без исключения блоков вокруг цели. Отдельный бюджет: до 1024 лучей, 32768 обходов блоков и примерно 1 мс накопленного времени трассировки на кадр. Время одного луча может превысить остаток бюджета. Ограниченный 16384 записями кеш по ячейкам 1/8 блока живёт до 20 кадров, сбрасывается при движении камеры, изменениях блоков/настроек и смене мира. Необслуженные ячейки проходят через ограниченную FIFO-очередь (до 4096), которая обрабатывается раньше новых запросов следующего кадра. Перегрузка не становится доказательством скрытости: объект остаётся видимым.

Это целенаправленно более агрессивный способ для частиц, чем девять лучей для механизмов. Если центр за препятствием, вся частица скрывается, даже если край выступает. Возможны ошибки у узких отверстий и небольшие различия внутри кеш-ячейки. Стандартные частицы с нестандартным смещением собственного рендера могут требовать отдельного адаптера. Сторонние системы, обходящие ParticleEngine, не перехватываются. Максимальная дистанция проверки — 128 блоков; Sable-позиции и неготовые Sable-контейнеры исключены. Нет обещания, что любой эффект за любой модовой моделью будет скрыт.

## Меню

Семь разделов по объектам вместо восьми разделов по поколениям функций. Скрытие частиц, обычных моделей Create, моделей Flywheel и пауза анимаций имеют один переключатель режима: выключено / непрозрачные / любые препятствия. Связанные параметры находятся рядом. Дальность и интервал недоступны, если их функция выключена, мод отсутствует или действует полное диагностическое отключение. Подсказки объясняют зависимость.

Разрежение тиков — единый выбор: выключено, непрозрачные препятствия, любые препятствия, дальность, EntityCulling. Последний вариант предлагается только при наличии мода. Старые значения JSON сохраняются; при конфликте UI показывает прежний фактически приоритетный режим. При выборе другого режима конкурирующие флаги сбрасываются. Видимость линий панелей также объединена: все / только рядом / не показывать.

Обычные модели Create и Flywheel оставлены отдельными, потому что это разные пути рендера. Их названия и подсказки объясняют разницу. Ограничитель API Flywheel и оптимизации трёх конкретных визуализаций также имеют разную область действия. Полное скрытие вынесено в «Диагностика: отключения» и имеет явные названия. Включать все настройки подряд не требуется.

## Проверка в пользовательской сцене

1. Заменить старый JAR. Оставить общий Slopium включённым.
2. В диагностике выключить полное отключение частиц.
3. В разделе «Частицы» выбрать «Скрывать частицы за препятствиями → За любыми блоками». Для чистого сравнения отключить ограничение появления и скрытие по дальности.
4. Сравнить окно с режимом «Выключено» и «За непрозрачными блоками». При открытии прохода/удалении окна частицы должны возвращаться. Обычные статические модели механизмов за стеклом могут оставаться: это не частицы и не специальные модели Create.
5. Если эффекты остаются, строка `/slopium status` → `Particle visibility` различает отсутствие вызовов, перегрузку проверок и защиту Sable. Нужен тип оставшегося эффекта для определения стороннего пути рендера.

FPS в пользовательской сцене ещё не измерен; изменение алгоритма может как сэкономить рендер, так и добавить CPU-работу. Итог оценивать по времени кадров при одинаковой сцене.

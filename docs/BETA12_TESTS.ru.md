# Бета 12: отсечение секций

Дата проверки: 5 ноября 2026. Minecraft 1.21.1, NeoForge 21.1.242, Sodium 0.8.13, Create 6.0.11, Flywheel 1.0.6, Java 21. Тестовые клиенты и миры находятся в `run/smoke-*`; пользовательская установка не изменялась.

## Поведение

«Общее и свет → Куллинг чанков» содержит выключенный по умолчанию тумблер, минимальный радиус и выбор непрозрачных / любых препятствий. Радиус измеряется в секциях 16×16×16 по максимуму расстояний X/Y/Z. При 0 защищена секция камеры, при 2 — куб с радиусом две секции. Верхняя граница строго меньше текущей дальности прорисовки. Внутри радиуса сохраняется обычное поведение Sodium.

Название «Прогрузка только видимых чанков» соответствует запросу, но функция управляет **отрисовкой**, а не сетевой загрузкой. Данные чанков, клиентские тики и серверные механизмы не отключаются. В невидимой секции можно пропустить визуальные обновления Flywheel, не останавливая клиентские тики механизмов.

## Реализация и стоимость

- Sodium продолжает собственное отсечение по камере и связности. Дополнительная маска удаляет скрытые секции из команд terrain renderer, сохраняя порядок прозрачных проходов.
- Один результат для секции используется terrain renderer, обычными моделями блоков и индексом Flywheel. Проверка секции стоит перед индивидуальной проверкой модели и не зависит от списка выбранных блоков Create.
- Общий VisibilityPool обрабатывает запросы до индекса Flywheel. Результаты читаются каждый настоящий кадр, повторная трассировка каждый кадр не требуется. При первом появлении секции запрос попадает в очередь; немедленное сокрытие всех новых секций не гарантируется.
- Центральный луч лишь находит кандидата в препятствия. Для сокрытия нужен непрерывный срез стены, покрывающий всю перспективную проекцию секции. Проверяются реальные формы блоков, включая тонкое стекло; отверстия не заменяются сплошными кубами.
- Подтверждённая скрытая секция остаётся в кеше до движения камеры или изменения геометрии стены. Изменения посторонних колонок не сбрасывают доказательство. Переключение режима, радиуса, мира и дальности сбрасывает соответствующий кеш.
- Для общего планировщика сохранён ориентир 0,75 мс, из него 0,25 мс зарезервированы объёмным проверкам. До 128 доказательств за проход, до 256 ячеек стены на кандидат, не более 8192 записей секций. Это мягкий бюджет: единичная операция, JVM или драйвер могут его превысить. Обход списков Sodium и индекс Flywheel измеряются отдельно.
- Неизвестный или недоказанный результат оставляет секцию видимой. Новая стена не используется до готовности её меша Sodium. При движении камеры старое доказательство terrain сразу перестаёт действовать; восстановление экземпляров Flywheel проходит через его существующую ограниченную по времени очередь.
- Кеш команд Sodium сбрасывается только при изменении маски секций. Постоянного пересоздания мешей или нового GPU-прохода глубины нет.

GPU-вариант в эту версию не добавлен: существующий GPU depth Flywheel не выдаёт готовую маску секций Sodium и не покрывает режим любых препятствий без дополнительных данных. Дополнительный проход и синхронизация требуют отдельного сравнения; сами по себе они не гарантируют выигрыш.

## Проверки

`build/beta12-sections-verified.log`: реальный игровой мир и 11 последовательных состояний. Проверялись не только результаты алгоритма, но и маска региона Sodium, исключение команд и `sectionHidden` владельца экземпляров Flywheel:

| Состояние | Секция и Flywheel скрыты |
|---|---|
| Стекло, любые блоки | Да |
| То же стекло, непрозрачные | Нет |
| Каменная стена, непрозрачные | Да |
| Минимальный радиус включает цель | Нет |
| Тумблер выключен | Нет |
| Повторное включение | Да |
| Стена удалена | Нет |
| Стекло установлено вновь, любые | Да |
| Переключение на непрозрачные | Нет |
| Возврат к любым | Да |
| Камера перенесена сбоку от стены | Нет |

Геометрические проверки `SmokeSectionChecks`: сплошная стена, отверстие вне центрального луча, стекло, соединённые и раздельные панели, плита, исчерпанный бюджет, неготовый меш, секция камеры, расстояние 512 блоков, положительные и отрицательные направления трёх осей.

52 модульных теста прошли, включая пять тестов трёхмерного радиуса и строгой верхней границы. Проверка реальных Sodium controls дополнительно изменяет ещё не сохранённую дальность 12 → 5 и проверяет предел слайдера 11 → 4, значение 0 и недоступность зависимых настроек при выключенном тумблере.

`build/beta12-full-ui.log`: проверки интерфейса и геометрии прошли с полной референсной сборкой; английское меню проверено по снимку настоящего Reese’s Sodium Options. Русское меню также просмотрено. Наборы переводов совпадают: 262 ключа; в конфигурации 57 уникальных mixin-классов. Тестовый мод в JAR не включён.

`build/beta12-full-world-diagnostic2.log`: все 11 игровых состояний повторно прошли с полной референсной сборкой, включая Sable, Azimuth, Distant Horizons и Better Chunk Loading. Первые запуски на свежем мире не прошли таймауты: сначала целевая секция не имела меша, затем ожидаемая секция оставалась видимой. После подготовки области и повторного открытия уже созданного тестового мира проверки прошли без изменения рабочего алгоритма. Это не доказательство мгновенного отсечения при загрузке: пока состояние не подтверждено, геометрия остаётся видимой. Вспомогательный запуск с повторным открытием был отдельно прерван на предупреждении об экспериментальном мире; тестовый сценарий теперь обрабатывает это предупреждение только для собственных тестовых сохранений.

## Измерения и ограничения

В небольшом игровом стенде (6–8 секций в кеше), после начального прогрева общий планировщик стоил примерно 0,003–0,016 мс за проход; обход списков регионов — 0,004–0,010 мс за кадр. Начальная фаза: 0,023 и 0,014 мс соответственно. Это измерения CPU-обработчиков, **не доказательство прироста FPS на заводе**. Счётчик `skipped commands` считает исключения при перестроении команд, а не все кадры, использующие готовую скрывающую маску.

В успешном прогоне полной сборки обход списков занимал 0,006–0,026 мс за кадр в активных режимах после первой фазы (первая фаза — 0,057 мс). Эти цифры также относятся к небольшому стенду и не включают весь рендер Minecraft.

Для собственного сравнения: одинаковая позиция, направление, дальность и завершённая загрузка; генерацию кадров выключить. После прогрева каждого режима выполнить `/slopium reset`, подождать одинаковое время и сравнить `/slopium status`. Оценивать время настоящего кадра и p95, а также общую стоимость VisibilityPool, `lists ms/frame` и Flywheel. В открытой местности дополнительные проверки могут не окупиться.

Алгоритм консервативный: сложная комбинация стен без подходящего сплошного среза может остаться видимой. При движении и недостатке бюджета скрытие может появляться с задержкой. Польза выше за большой близкой стеной, закрывающей много геометрии. Поведение при 32 чанках и FPS на пользовательском сервере этим стендом не измерены.

Маска относится к геометрии секций Sodium и моделям блоков с подходящими границами. Сущности, частицы и Distant Horizons LOD этой функцией не отсекаются; для них сохраняются отдельные настройки. Виртуальные/подвижные миры Sable защищены от решений по статической геометрии. Проверка не заменяет отдельные алгоритмы для движущихся конструкций.

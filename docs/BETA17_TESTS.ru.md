# Slopium Бета 17: сокращение накладных расходов

9 ноября 2026. Minecraft 1.21.1 / NeoForge. Изменения сделаны по локальному аудиту `analysis/audit-20261109`, а не по предположению, что любая дополнительная проверка автоматически увеличивает FPS.

## Что удалено или объединено

- Удалены четыре mixin, подменявшие GPU-поля скорости/угла вращения и UV-прокрутки, и интерфейсы PausedRotation/PausedScroll. Эта остановка сохраняла draw/шейдерную работу и добавляла dirty-записи. CPU-приостановка визуалов оставлена, её название и подсказка исправлены на RU/EN: вращение в шейдере продолжается.
- Удалён отдельный Slopium-переключатель обычных теней сущностей, его mixin и счётчик. Этим управляет настройка Minecraft. Старый активный `disableEntityShadows` однократно переносится в vanilla-параметр; при выключенном Slopium старый флаг только сбрасывается. Миграция выполняется самим модом при запуске, пользовательская установка во время разработки не изменялась.
- Убран отдельный UI-тумблер отсечения трещин разрушения. Существующий дешёвый внутренний hook сохранён, старое JSON-поле читается для совместимости.
- Удалены runtime-ветки старого throttleFlywheelDistance: старый конфиг уже мигрирует в единый throttleCreateVisuals.
- Статистика выделена в группу диагностики. Полные отключения явно обозначены диагностикой; дополнительный GPU-куллинг — экспериментом с возможным отрицательным эффектом. Оба вида GPU-отсечения по умолчанию выключены. Настройки качества частиц, предметов и панелей сохранены: нулевой эффект в сцене без таких объектов не доказывает их бесполезность.
- Из плана анализатора убраны независимые пробы удалённого shadow-тумблера и внутренней оптимизации трещин. Генерация кадров остаётся независимой от включения остальных оптимизаций.

## Что удешевлено

1. Тик BE сразу возвращается в штатный путь, если ни одна политика тиков не включена. Выбор блоков проверяется один раз в этой цепочке. Результат фильтра кешируется в BE с revision и identity блока; смена списка/блока инвалидирует его.
2. BE хранит ленивую прямую ссылку на запись существующего VisibilityPool. Это тот же общий пул с двумя масками препятствий, а не отдельный второй кеш. Повторные BE-запросы не создают Key/Vec3 и не ищут запись через HashMap. Ссылка инвалидируется при смене мира/очистке пула/удалении записи.
3. Revision frustum меняется только при изменении матриц/камеры. Отдельно отмечается кадр, в котором камера подтверждена. При неподвижной камере одинаковые bounds не проверяются заново каждый кадр. До захвата камеры текущего кадра тики не получают renderer/AABB ради проверки, которая всё равно недоступна. Неизменившийся AABB повторно не inflate-ится.
4. Неактивные правила BER и visual updates не выполняют фильтрацию/unwrap. Наличие visibleSections само по себе больше не включает CPU-политику visual updates.
5. Владение Flywheel создаётся по необходимости: 0 — штатный контекст; 1 — только метаданные для CPU-обновлений; 2 — также отслеживание экземпляров для сокрытия. Переходы пересоздают только уже существующие block visuals после завершения tick-workers. Обычные visual хранят прямую ссылку на метаданные; для сторонних обёрток сохранён map-fallback. При известном владельце повторный unwrap не выполняется.
6. Запрос GPU-маски больше не означает, что выбранные модели действительно обслуживает GPU. Для BLACKLIST/WHITELIST, которые shader секций пока не умеет учитывать, запрос секционного прохода не выключает CPU fallback выбранных моделей. Режим ALL не навязывается.
7. Create.applyOverstressEffect не помечает RotatingInstance изменённым, если стресс-эффект равен нулю и все RGB уже белые. Само вращение/RPM/освещение не отключаются. Изменение стрессовой окраски и возврат к белому проходят через исходный Create-код.
8. LightGrid при 0–16 источниках больше не строит корзины, которые его линейная ветка не использовала. Формула света сохранена.

## Анализатор и ZGC

Формат отчёта — schema 3. quality.gcMillis/gcCount теперь означают время/число известных GC pause beans. Отдельно записаны collectors с count, millis и kind=PAUSE/CONCURRENT/UNKNOWN. Конкурентные ZGC/Shenandoah Cycles не отбраковывают замер как остановку игры. Неизвестные collectors сохраняются и дают предупреждение о неполноте pause time; их время не объявляется паузой. Старые отчёты не переписывались и не исправлялись задним числом.

## Проверки

- `gradlew build`: 63 JUnit-теста, 0 ошибок/падений. Добавлены проверки разделения ZGC cycles/pauses, неизвестного GC и точного света для малого снимка.
- Целевые smoke на legacy и полном наборе reference/mods: реальные mixin-точки, pane/door/slab/opening, общий пул, отсутствие лучей у читателей, инвалидация прямой ссылки, неподвижная камера на 50 кадрах без повторных frustum tests, изменяемые bounds, фильтры, GPU/CPU routing, частицы, свет, панели, UI, native FSR и reprojection shaders.
- Полный тестовый мир: реальные shaft/press/chain conveyor, ALL/WHITELIST/BLACKLIST, выключение/включение и переход между mode 1 (CPU-only) и mode 2 (отслеживание instances). В CPU-only нет отслеживаемых экземпляров; при отключении нет ownership-обёрток; модели восстанавливаются. В full-профиле также загружены Azimuth/Sable.
- Отдельный интеграционный запуск `-PanalysisSmoke -PzgcSmoke` со Spark: реальный мир, параллельный вывод, свёрнутое окно, восстановление настроек/неизменный конфиг, запись schema 3, декодирование клиентских Spark call trees и сохранение чужого sampler ownership. Во время коротких FPS-проб GC-событий не было; ненулевой concurrent delta проверен отдельным JUnit-тестом (1500 мс cycles, 1 мс pauses).
- Минимальный профиль без Create/Flywheel: запуск, optional mixin guards и английские экраны успешно проверены (`build/beta17-base-smoke.log`).
- RU/EN: по 280 ключей. На полном наборе модов зарегистрированы 65 уникальных controls, проверены зависимости и числовой ввод. Экраны реально открыты и просмотрены; длинная подпись CPU-анимаций сокращена после обнаруженного наложения.
- Проверена упаковка JAR: удалённых mixin-классов нет, все заявленные mixin-классы присутствуют, smoke/Spark implementation не встроены, logo.png побайтно совпадает с reference/logoT.png.

Команды успешных целевых запусков и логи:

```powershell
.\gradlew.bat build runSmokeClient -PwithReferenceMods -PsmokeProfile=full -PoptimizationSmoke --offline --console=plain
# build/beta17-final-ui.log
.\gradlew.bat build runSmokeClient -PwithReferenceMods -PsmokeProfile=full -PworldSmoke -PoptimizationSmoke --offline --console=plain
# build/beta17-full-world.log
.\gradlew.bat build runSmokeClient -PwithReferenceMods -PsmokeProfile=legacy -PworldSmoke -PanalysisSmoke -PzgcSmoke -PsectionSmokeReuse=framegen-beta2-1793916113089 --offline --console=plain
```

`optimizationSmoke` запускает относящиеся к изменению проверки и функциональные shader-тесты FG, но исключает старый длительный SmokeFrameLifecycleChecks с требованиями к числу синтетических кадров. Один запуск полного legacy-набора остановился на `No adaptive synthesis in FSR` при deadline-нагрузке: build/beta17-legacy-smoke4.log. Этот тайминговый тест не объявляется пройденным; код генерации кадров не менялся. Функциональные FSR dispatch/motion/HUD тесты и отдельный реальный parallel-output/analyzer сценарий прошли. Это не доказательство устойчивой производительности генерации при любой нагрузке.

## Измерение и ограничения

В `analysis/beta17/clean-color-cpu-abba.json` сохранены 16 измерений ABBA одного участка: 8192 синтетических RotatingInstance, 100 обновлений неизменной окраски, общий одинаковый массив, один прогрев. Последний full-запуск: медиана исходного участка **1.485 мс**, с проверкой no-op **0.567 мс**; dirty-вызовы **819200 → 0**. Обработчик dirty в этом тесте — счётчик, а не весь настоящий GPU upload. Это CPU-микротест, не замер FPS мира и не измерение стоимости Flywheel uploads на пользовательском заводе.

Нет нового A/B в пользовательском городе, поэтому не заявляется процент FPS или достижение 60/400 FPS. Дополнительный GPU depth pass не переписан и не объявляется ускорением; у него сохраняются экспериментальные ограничения и гранулярность 16³. Избирательная GPU-маска с BLACKLIST/WHITELIST ещё не реализована: используется ограниченный CPU fallback. CPU-видимость остаётся отложенной и не превращается в точную пиксельную карту текущего кадра. Из Nvidium код не переносился: замена terrain backend не является дешёвой оптимизацией Create tick.

Повторное измерение следует делать встроенным анализатором в той же заводской сцене, со стабильной внешней нагрузкой. Новые отчёты ZGC пригоднее для этого, но короткий тестовый мир и микротест не заменяют такое сравнение.

Артефакт: `build/libs/slopium-neoforge-1.21.1-beta-17.jar`. Хеш и состав сборки: `analysis/beta17/build.json`. Все запуски использовали отдельные `run/smoke-*`; пользовательские Minecraft-папки, моды, конфиги и миры инструментами разработки не изменялись.

# Alpha.17: использовать существующий GPU-путь Flywheel

## Реализация

Flywheel 1.0.6 содержит DepthPyramid и GPU-куллинг в indirect/cull.glsl. Slopium определяет реально созданный движок через VisualizationManagerImpl.getEngineImpl().drawManager(), а не по настройке предпочтительного backend. Отсутствующий движок и другие backend сохраняют CPU-путь.

При включённом скрытии моделей за непрозрачными препятствиями на IndirectDrawManager CPU-скрытие Slopium не выполняется. Если нет запросов паузы анимаций, очередь поддержанных визуализаций не обходится. События создания/удаления продолжают обрабатываться для последующих переключений. При передаче управления ранее скрытые экземпляры восстанавливаются в пределах прежнего бюджета. Штатный GPU затем решает, рисовать ли их. Slopium не получает этот ответ на CPU.

Пауза анимаций требует собственной CPU-проверки даже при таком же непрозрачном режиме. Она не подменяется значением «видим», используемым для передачи моделей GPU. Режим «за любыми блоками» сохраняет прежнее выборочное скрытие на CPU. Смена backend входит в ключ политики и запускает корректное восстановление.

Это уменьшение дублирующей работы, а не новый GPU-движок. Штатный Flywheel-куллинг действует и без включения настройки Slopium. Не добавлены GPU-буферы, синхронные чтения, рабочие потоки или дополнительные проходы глубины. Неподдерживаемые CPU-путём визуализации не стали поддерживаемыми за стеклом.

## Проверки

Сборка, 21 unit-тест и full/legacy/minimal запуски прошли. Итоговые логи: `build/alpha17-full.log`, `build/alpha17-legacy.log`, `build/alpha17-minimal.log`.

Новый интеграционный тест вызывает настоящий внедрённый hook VisualizationManagerImpl на тестовой сцене с большой шестернёй и дополнительным валом. Для проверки выбора пути в тестовый движок устанавливается IndirectDrawManager без выполнения OpenGL-команд. Проверяется:

- передача ранее скрытых экземпляров штатному GPU-рендереру;
- отсутствие CPU-запросов видимости и оценок визуализаций за 24 установившихся кадра при режиме только моделей;
- сохранение CPU-паузы анимаций при делегированных моделях;
- сохранение режима любых препятствий на indirect;
- возврат CPU-режима при недоступном indirect и восстановление при выключении.

Этот тест проверяет маршрутизацию и состояние экземпляров, а не фактическую картинку GPU-куллинга. Старые тесты двух backend, квот, стабильности, вращения, частиц и кешей сохраняются. Фактический FPS пользовательского мира не измерен.

## Проверка в игре

Заменить предыдущий JAR, перезапустить игру. Выбрать непрозрачный режим моделей Flywheel. Строка Flywheel path в /slopium status должна показывать native GPU depth=true и opaque models delegated=true при реально активном indirect. При выключенной паузе анимаций очередь Slopium не должна постоянно оценивать модели. Другие функции всё ещё могут создавать CPU-лучи.

Сравнивать одинаковые настройки и ракурс после прогрузки. При режиме любых блоков новая оптимизация не применяется. Пауза анимаций не должна исчезать при переключении на GPU-путь моделей. Проверить возврат моделей после выключения настроек. На границе препятствия штатный объёмный GPU-тест может оставить модель видимой там, где CPU-луч к центру блока скрывал её.

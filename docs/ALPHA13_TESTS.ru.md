# Alpha.13 — Flywheel Indirect: видимый экземпляр ошибочно считался скрытым

## Пользовательский результат alpha.12

Установленная alpha.12 и включённые режимы проверки любых препятствий подтверждены чтением mods, config/slopium.json и latest.log. Пользователь передал:

- Create visibility: checked=11431573, rays=140141, cache=264716, deferred=9175660, Sable protected=0.
- Flywheel visibility: checked=6167187, wrapped=229745, unsupported=3256097.
- Walls: Create draws=30222, Flywheel instances=0.
- Последний замер кадров: n=341, 15.5 s, avg=22 FPS, p50=46.55 ms, p95=61.20 ms.

Счётчики накопительные и не обязательно охватывают тот же период, что Frames. Около 80.3% запросов Create отложены; около 52.8% обойдённых визуализаций Flywheel неподдерживаемые. Нулевой результат Flywheel сохраняется даже после появления распознанных обёрток Azimuth. Эти данные не доказывают, что именно куллинг вызвал 22 FPS: для этого нужен замер с выключением одного режима при неизменной сцене.

## Подтверждённый дефект

В бинарнике Flywheel 1.0.6 метод InstanceHandleImpl.isVisible() проверяет `state instanceof AbstractInstancer`. Это работает с InstancedInstancer. IndirectInstancer хранит живой handle в InstancePage, который реализует State, но не наследует AbstractInstancer. Видимый экземпляр возвращает false, и проверка Slopium перед setVisible(false) не пропускает его к скрытию.

Новый регрессионный тест создал настоящий IndirectInstancer/InstanceHandleImpl и подтвердил: instanceCount=1, isVisible=false, state=IndirectInstancer$InstancePage. Прежний код сохранил экземпляр в списке вместо скрытия, тест завершился AssertionError. Лог: build/alpha13-repro-indirect.log. Тест Instancing в том же запуске прошёл. Это объясняет, почему прежняя проверка одного backend не обнаружила дефект.

Исправление находится в локальной проверке InstanceVisibility: точно известное живое состояние Indirect учитывается как видимое. Состояния Hidden/Deleted и неизвестные типы автоматически видимыми не считаются. Дополнительно восстановление проверяет индекс handle: в 1.0.6 удаление скрытого экземпляра оставляет состояние Hidden, но сбрасывает индекс в -1. Такой экземпляр больше не восстанавливается. Метод API Flywheel глобально не подменяется. Нет новых настроек, смены backend или изменения серверной логики.

## Проверки

Тест SmokeInstanceBackendChecks выполняет один сценарий для двух настоящих backend: создание экземпляров, сохранение ранее скрытого экземпляра, скрытие Slopium, восстановление, удаление. Проверяются реальные счётчики экземпляров после compaction, возможность вернуть отдельно скрытый экземпляр, отсутствие воскрешения удалённого скрытого экземпляра. Фикстура не рисует полноценный игровой мир и не измеряет время GPU.

Интеграционные проверки стекла, непрозрачных препятствий, обёртки Azimuth, расширения BnB, замены модели, раздельных режимов анимаций и очереди Create сохранены. Они описаны в ALPHA12_TESTS.ru.md. Подробные результаты запусков и состав JAR записываются в VALIDATION.ru.md и analysis/slopium-alpha13-build.json.

## Цена куллинга

При включённой диагностике строка `Culling cost` содержит:

- Flywheel passes: число выполненных проходов Slopium.
- avg/max: среднее/максимальное CPU-время одного прохода, включая обход, проверку видимости, применение скрытия и паузы. Это не время GPU и не обязательно один проход на кадр.
- Create trace total: накопленное CPU-время трассировки Create со всех вызывающих путей. Оно частично входит во время Flywheel; складывать эти величины нельзя.

Около 1 мс ограничивает накопленное время трассировки за кадр, но не все поиски в кеше, обходы моделей, обновление экземпляров и прочие издержки. Скрытие приносит пользу, когда исключённая работа дороже этих расходов. Пауза GPU-вращения сама по себе не убирает модель из отрисовки. Поэтому тест сравнивает время кадров и фактическое скрытие, а не только счётчик проверок.

Установка: заменить предыдущий JAR Slopium одним alpha.13 и перезапустить клиент; конфигурацию сохранить. Проверить у прежнего окна значение «Скрывать модели Flywheel → За любыми блоками» с закрытым меню. Для замера выполнить /slopium reset и измерять 30–60 секунд без движения камеры; записать Walls, Create visibility, Flywheel visibility, Culling cost и Frames. Сравнить с отключённым скрытием Flywheel при остальных прежних настройках после стабилизации. Если нужно оценить все расходы этой политики, отдельно выключить паузу анимаций за препятствиями, которая использует тот же обход.

Статические корпуса в геометрии чанков, неподдержанные визуализации аддонов и дополнительные цепи BnB не охвачены. Sable-области защищены. Реальный FPS сервера и визуальный результат конкретного окна в alpha.13 ещё не проверены.

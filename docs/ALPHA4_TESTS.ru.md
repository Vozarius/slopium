# Alpha.4: тестовые отключения

Настройки графики → Slopium → Тестовые отключения. Все новые опции выключены по умолчанию, общий выключатель Slopium отменяет их действие. Старые значения конфигурации сохраняются.

| Переключатель | Что исключается | Что остаётся |
|---|---|---|
| Не рисовать блочные сущности | Вызовы мирового BlockEntityRenderDispatcher.render | Обычные модели блоков, тики, пакеты, отдельный рендер Flywheel |
| Не рисовать Flywheel | InstancedDraw.render/renderOne, IndirectCullingGroup.submitSolid/submitTransparent, трещины EngineImpl.renderCrumbling | Обновления визуализаций, обслуживание и загрузка буферов, вычислительный куллинг; fallback использует обычный BER |
| Отключить частицы | Добавление и рисование через стандартный ParticleEngine | Старение существующих частиц; сторонние системы эффектов могут продолжать работать |
| Отключить фоновые эффекты блоков | ClientLevel.animateTick, включая ambient-эффекты блоков и жидкостей | Серверные random ticks, обычные клиентские тики и обновления состояний |
| ДИАГНОСТИКА: заморозить тики Create | Клиентский тик инициализированных SmartBlockEntity, в том числе видимых и подклассов из дополнений | Первичная инициализация, приём пакетов, серверные тики; виртуальные миры и Sable-защищённые позиции исключены |

Заморозка может нарушить местные анимации, отображение жидкостей, индикаторы и клиентскую часть взаимодействия. Серверный механизм продолжает работать, но это не гарантия нормального поведения клиента. Только для краткого замера: выключить после него, при оставшихся артефактах переподключиться. Серверная сторона отсеивается до обращения к Minecraft. Для одного игрока встроенный сервер также не замораживается.

Отключение рисования не делает механизмы проходимыми: физика и выбор блоков не изменяются. Не следует взаимодействовать со скрытыми механизмами, ориентируясь только на оставшуюся картинку.

Это не полное отключение всех визуальных обновлений Minecraft: меши чанков, обычные сущности, сеть и DH не отключены. Новый универсальный окклюзионный куллинг не добавлен; прежнее разрежение скрытых Create-блоков и EntityCulling работают как раньше. Цель этой версии — проверить предел выигрыша от удаления самых затратных категорий, прежде чем писать сложный избирательный куллинг.

## Порядок измерений

1. Заменить старый Slopium на alpha.4, не держать два JAR. Оставить прежние настройки DH, дистанцию, фоновые программы и остальные опции неизменными.
2. Включить диагностику Slopium. В тяжёлом месте зафиксировать позицию и направление камеры. Сначала все новые опции выключены.
3. После применения настроек дать сцене стабилизироваться (применение также перестраивает чанки). Выполнить `/slopium reset`, закрыть чат, 60 секунд не открывать меню. Сохранить все строки `/slopium status`.
4. Повторить отдельно для BER, Flywheel, частиц, фоновых эффектов, каждый раз возвращая остальные тестовые опции в исходное положение. Затем сравнить BER + Flywheel вместе. Только после этого отдельно попробовать заморозку.
5. Повторить исходный вариант для проверки дрейфа нагрузки. Сделать те же замеры на втором клиенте. Для лучшего режима снять Spark-профиль и проверить вращение камеры, переключение режима обратно и переподключение.

Строка Tests считает пропущенные вызовы, а не объекты. Счётчик Flywheel может увеличиваться несколько раз за кадр. Эти числа подтверждают срабатывание, но не измеряют сэкономленное время. Главные показатели — avg FPS, p50/p95/p99 времени кадра. Сравнение проводить с одинаковым состоянием диагностики. 60 FPS в исходном мире этой сборкой пока не подтверждены.

# Alpha.18: камера и экспериментальная GPU-глубина стекла

## Архитектура

CPU: VisibilityPool содержит ответы по стенам и отдельный результат по объёму относительно камеры. Камера захватывается из матриц renderLevel. Одна запись разделяется по позиции и семантике цели (механизм/частица); проверка камеры инвалидируется новым захватом матриц, включая несколько захватов в одном кадре. Проверяются объёмы рендереров/частиц, а не только центры. Неизвестная камера, бесконечные bounds и Sable-защита не скрываются. Тумблер сам по себе не останавливает клиентские тики; проверка камеры дополняет выбранный режим скрытых обновлений.

GPU: EngineImpl.render предоставляет RenderContext на время вызова с восстановлением в finally. DepthPyramid.generate получает альтернативный RenderTarget, только когда включён GPU-тумблер, выбран любой блок и используется indirect. RenderTarget содержит копию основной глубины и глубину дополнительного прохода готовых прозрачных мешей Sodium. Нет нового обхода блоков/построения мешей. Цветовой вывод дополнительного framebuffer отключён. Затем Flywheel выполняет прежний compute shader: frustum AND depth visibility, с записью индексов для отрисовки в GPU-буфер. Второй GPU-куллинг поверх штатного не добавлен.

CPU и GPU не используют один физический буфер: каждый путь объединяет камеру/стены у себя. Для тиков и анимаций нет синхронного чтения GPU. GPU-режим за стеклом относится к моделям Flywheel, не к обычным моделям Create или частицам.

## Ограничения

- Это тестовый режим, по умолчанию выключен. Стоимость дополнительного прохода может превысить выигрыш, особенно при большом количестве воды/стекла и ограничении по GPU.
- Дополнительный RenderTarget выделяется по разрешению окна, переиспользуется, пересоздаётся при смене размера/мира, освобождается при выключении настройки и выходе с сервера. Помимо штатной пирамиды он занимает память под depth/color attachments; цвет не используется для вывода.
- Препятствия — отрисованные поверхности чанков. Стекло/вода учитываются, отверстия в мешах остаются открытыми. Специальные рендереры и невидимые формы блоков не дополняются отдельным обходом. Это не точное повторение семантики CPU-луча по VoxelShape.
- С установленными Iris/Oculus, Fabulous или нестандартным текущим framebuffer GPU-путь не используется. При исключении он отключается до изменения настроек; исходный target сохраняется. Ошибка не должна превращать скрытие в обязательное ожидание GPU.
- Flywheel на GPU проверяет объём каждой модели. У края препятствия модель может оставаться видимой дольше, чем при CPU-луче к центру. Статическая геометрия блоков не скрывается настройкой моделей Flywheel.
- Штатный frustum-куллинг движков остаётся включён независимо от нового тумблера. На CPU-пути Flywheel применение ограничено его очередью, поэтому новая камера не гарантирует мгновенное изменение всех экземпляров.

## Проверки

Итоговая сборка и 21 unit-тест прошли. Успешные итоговые клиенты: `build/alpha18-full-verified.log`, `build/alpha18-legacy-verified.log`, `build/alpha18-minimal.log`. Метаданные JAR: `analysis/slopium-alpha18-build.json`.

Новый GPU-тест действительно рисует четырёхугольник в отдельный OpenGL framebuffer: глубина результата 0,25, исходная остаётся 0,75. Проверяет восстановление framebuffer после успешного прохода и исключения, а также отсутствие GL-ошибки. Это проверка построения изолированной глубины, не полноценная сцена Sodium с заводом за окном.

NeoForge уже проверяет частицы, если передан штатный frustum. Slopium не выполняет второй тест в этом случае; дополнительная проверка работает при отсутствии frustum. Отдельный тест вызывает реальный ParticleEngine с обоими вариантами.

Тест камеры проверяет переднюю/заднюю область, частично попавший в пирамиду объём, смену направления даже в том же кадре, выключатель, отсутствие повторных проверок за 100 обращений и одну запись с проверкой стен. Старые интеграционные тесты проверяют частицы, окна/двери, backend Flywheel, GPU/CPU-переключение и восстановление. Дополнен тест включения/выключения GPU-делегирования любого блока на indirect.

В интерфейсе 48 уникальных переведённых параметров. Фактическая сцена пользователя и прирост FPS не проверены.

## Проверка в игре

1. Заменить JAR, перезапустить клиент. Сохранённые настройки можно оставить.
2. В «Общее и свет» включить нужные новые тумблеры. Для GPU-стекла также выбрать «Скрывать модели Flywheel → За любыми блоками».
3. При backend indirect строка `Flywheel path` показывает делегирование моделей. `GPU glass` должна показывать `GPU terrain depth`; при включённой диагностике растёт passes. Если указан fallback, работает прежний CPU-путь.
4. Сравнить 30 секунд одного ракурса с GPU-тумблером и без него после прогрузки. Перед замером `/slopium reset`. Нужны Frames, GPU glass, Camera culling и Flywheel path.
5. Проверить окно, открытую дверь, поворот камеры, изменение размера окна и выключение новых настроек. Время CPU submit в диагностике не выдавать за GPU-время.

Один повторный полный запуск завершился до smoke-тестов ошибкой регистрации Create/Registrate «Found unused register callbacks». Лог сохранён как build/alpha18-full-final.log; это не результат проверки GPU-прохода.

Следующий полный запуск дошёл до тестов, но старый тест вызывал обработчик частиц с четырьмя аргументами вместо пяти после добавления штатного frustum. Обновлён тестовый вызов; этот сбой не был ошибкой игрового вызова ParticleEngine. Лог: build/alpha18-full-retry.log.

# Бета 18: появление скрытых моделей Flywheel

## Причина

В Бете 17 скрытый visual попадал на повторную проверку через 8 кадров Slopium, затем мог ждать бюджет общей очереди. Сам VisibilityPool намеренно сохранял старый ответ «скрыто» при ожидании новой трассы. Для моделей это давало видимую задержку после открытия обзора. Дополнительно CPU wall-decision неявно применял frustum даже при native indirect GPU frustum.

## Изменения

- Перед обычной очередью добавлен возврат ранее изменённых visual при изменении положения камеры, frustum или геометрии. Он выполняется до Flywheel frame plan и не ждёт 350-мкс/512-entry бюджета обычного сокрытия.
- Поворот камеры перепроверяет только visual, чьё состояние зависело от frustum. Обычное настенное сокрытие не перепроверяется из-за одного поворота на месте. Диагностические «скрыть всё»/«приостановить везде» сохраняют смысл.
- Старого положительного луча в центр недостаточно для сокрытия модели. В общей записи VisibilityPool хранится форма уже найденного препятствия; проверяются углы полного render AABB с запасом. Если один реальный cuboid препятствия не доказывает перекрытие всего AABB, модель остаётся видимой. Это консервативный подход: сложные/составные препятствия могут отсекать меньше моделей.
- Политики непрозрачных/любых блоков используют ту же общую запись, с отдельно кешируемыми результатами проверки bounds. Форма препятствия обновляется по generation/version геометрии; проёмы не заполняются общим bounding box формы. Геометрия сложнее 16 cuboid не используется для такого доказательства.
- Быстрый путь не трассирует воксели. Он использует remembered blocker и slab-проверку восьми углов без выделения Vec3 на каждый угол. Доказательство кешируется по форме, bounds, положению камеры и политике.
- Неопределённый результат больше не удерживает модель скрытой или CPU-обновление приостановленным. Повторное сокрытие остаётся в бюджетной очереди. Нативный GPU-куллинг Flywheel и GPU-маска секций не переписаны.
- Возврат не переупорядочивает TreeSet очереди для каждого раскрытого visual. Владение новыми/заимствованными/удалёнными экземплярами и фильтры блоков сохранены.

Настройки, тики, сеть и серверная симуляция этим исправлением не меняются. Штатный GPU frustum не дублируется CPU-сокрытием модели из wall-decision.

## Проверки

`build/beta18-final-smoke.log`: успешны build и целевые проверки с полным набором reference/mods (Azimuth/Sable включены). Также прошёл legacy-профиль: `build/beta18-smoke4.log`.

- 69 JUnit-тестов, без ошибок/падений. Шесть новых проверок: закрытая стенка, выход из-за угла, частичная видимость AABB, касание/нахождение внутри препятствия, проём между cuboid, нечисловые координаты.
- Hook Flywheel проверен на настоящих классах Create large cog + дополнительный shaft, включая Azimuth wrapper: выход на другую сторону стены, удаление препятствия и возвращение во frustum восстанавливают handle видимости за **один вызов кадра**.
- В этих трёх регрессиях процессор мировых трасс намеренно не работал в кадре возврата. Для перехода на другую сторону проверено отсутствие новых world rays.
- 32 мелких движения камеры перед закрытой стеной не раскрывают модель. Сохранились проверки двух режимов препятствий, фильтров, переиспользования/замены экземпляров, native GPU routing и fallback.
- Прямой читатель общего пула не может скрыть частично открытый AABB. Углы проверяются по реальному cuboid, а не по общей коробке сложной формы.
- Массовый fixture: 12000 visual, 6000 поддерживаемых. Все **6000 ранее скрытых** восстановлены в одном кадре при выключенном процессоре трасс: **3.9808 мс**, **0 новых world rays**. Обычная очередь: максимум 512 проверок/кадр, средняя стоимость отдельного fixture-цикла **0.3288 мс**.
- Функциональные проверки частиц, освещения, UI, shader-генерации кадров и прежние интеграционные проверки также пройдены в целевом optimizationSmoke. Старый тайминговый SmokeFrameLifecycleChecks в этот набор не входит; его ограничение описано в BETA17_TESTS.ru.md.

Команда:

```powershell
.\gradlew.bat build runSmokeClient -PwithReferenceMods -PsmokeProfile=full -PoptimizationSmoke --offline --console=plain
```

## Ограничения измерения

Это интеграционный fixture с фактическими mixin/hook-методами и классами visual Create, но тестовыми миром и handle. Stress fixture повторно использует один BE для многих visual; его 3.98 мс нельзя считать стоимостью реального завода из 6000 разных блоков. Изменение пикселей пользовательской сцены и её FPS не измерялись. Полного обхода мира не добавлено; стоимость зависит от числа ранее скрытых visual и возвращаемых экземпляров.

Для возврата введён приоритет корректности: при массовом раскрытии нужно восстановить все необходимые экземпляры сразу, поэтому его нельзя одновременно ограничить 512 visual/350 мкс и гарантировать отсутствие задержки. Цена такого раскрытия видна в общем тайминге Flywheel culling; это может дать разовую нагрузку. Статическое/обычное сокрытие остаётся бюджетным. Видимые или сомнительные модели могут отрисовываться чаще, чем раньше.

«Один кадр» относится к настоящему рендеру мира. Генерация кадров не создаёт отсутствующую геометрию между настоящими кадрами. Возможная собственная задержка native Flywheel GPU HiZ этим CPU-исправлением не заменяется.

JAR: `build/libs/slopium-neoforge-1.21.1-beta-18.jar`. Проверки выполнялись только в `run/smoke-*`; пользовательская установка Minecraft не изменялась.

# Slopium — Бета 1

## Общий множитель

«Генерация кадров → Множитель кадров» принимает каждое целое значение от ×2 до ×32. Подпись показывает количество новых кадров: ×2 → 1, ×4 → 3, ×32 → 31. Предел вывода FPS остаётся отдельной настройкой; VSync и меньший лимит Minecraft не отменяются.

Последовательность для пары A/B: сначала A, затем позиции 1/N, 2/N, …, (N−1)/N, затем B. Следующая полная отрисовка нужна для новой пары. На прогреве, при повороте/перемещении камеры, паузе или смене настроек история может сброситься, поэтому фактическое соотношение иногда ниже выбранного.

Простой генератор считает прямые и обратные векторы один раз на пару изображений, затем использует их для всех промежуточных позиций. Готовые 31 изображения не хранятся: переиспользуется одна выходная текстура. Большие множители не требуют 32-кратного объёма VRAM.

## FSR

При ×2 работает прежний официальный FSR 3.1.6. При ×3–×32 используется гибрид **FSR 3 + Slopium**: SDK рассчитывает середину пары, Slopium — дополнительные позиции с опорой на исходные кадры, середину FSR и общее поле движения. Это не заявление о поддержке нативного FSR ×32. Для чётного множителя средняя позиция выводит непосредственно изображение SDK; нечётные множители также используют его в интерполяции. Добавляется одна полноразмерная текстура середины и поле движения, независимо от N.

Иная техника из [Screamix1/FrameGen](https://github.com/Screamix1/FrameGen) послужила примером интерфейса с множителем: там описана перепроекция последнего кадра по новой камере. Slopium продолжает использовать интерполяцию двух кадров; код FrameGen не копировался. Поэтому заявления FrameGen о задержке к Slopium неприменимы.

## Как проверить

Включить «Помечать сгенерированные кадры»: розовая полоса сверху появляется только на промежуточных изображениях; настоящие и прогревочные кадры не помечаются. Можно начать с ×4. В `/slopium status` выводится `Simple x4` либо `FSR 3.1.6 + Slopium x4`, счётчики реальной отрисовки, промежуточных кадров, готовых конечных кадров и обе частоты. Исправлен подсчёт выходного FPS для множителей больше двух.

Большие значения добавляют задержку и артефакты. При постоянном выводе 120 FPS множитель ×32 соответствует примерно 3,75 настоящим кадрам в секунду. Он пригоден прежде всего для эксперимента; 32-кратный прирост FPS не обещается. Затраты и нестабильные результаты прежних синтетических замеров описаны в [alpha.19](ALPHA19_TESTS.ru.md). Прирост в пользовательском серверном мире не измерялся.

## Версия и совместимость

В Sodium/Reese показывается «Бета 1» / «Beta 1». Имя JAR: `slopium-neoforge-1.21.1-beta-1.jar`. Техническая версия `1-beta.1` удовлетворяет требованию NeoForge о начальной цифре; строка `beta.1` была отвергнута загрузчиком в первоначальном тесте, журнал сохранён. Config сохраняет старые поля; новые по умолчанию: множитель 2, отметка кадров выключена. Исторические документы alpha и совместимый кеш нативного runtime не переименованы.

## Проверки

- Unit-тесты проверяют все множители 2–32 на нескольких последовательных парах: строго возрастающие позиции, конечные кадры, сброс и смена множителя.
- GPU-тест сравнивает позиции движущегося прямоугольника при t=0,25 и t=0,75 в простой и гибридной интерполяции: изображения различаются, а не повторяют средний кадр.
- Производственный обработчик проверяется на ×2, ×3, ×4, ×8, ×32 для обоих режимов. При ×32: 65 выводов, 3 полных отрисовки, 62 промежуточных кадра; по каждому выводу читается контрольный пиксель отметки. Проверяются глубина, пауза, ресурсы, выключение и ограничитель.
- Настройки: 56 параметров; множитель доступен для обоих режимов, параметры дополнительной интерполяции FSR становятся доступными выше ×2; OFF отключает зависимые элементы. Проверено изображение меню и подпись «Бета 1».

Результаты финальных запусков и SHA-256: `analysis/slopium-beta1-build.json`.
